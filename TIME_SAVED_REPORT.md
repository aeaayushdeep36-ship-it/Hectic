# Time-Saved Report

Submitted for the AI Agents for Founders Challenge.

**No manual baseline was timed in this project, so none is claimed here.** It
would be easy to write "six hours saved", but that number would be invented. The
figures below were measured on 2026-11-24 from the committed repository; each
one names the command that produced it.

| Measured operation | Result | How it was measured |
|---|---:|---|
| Clean install | 31 s | `npm ci` in a fresh copy with no `node_modules`; 215 packages, no C++ toolchain |
| Unit and integration tests | 0.649 s | `npm test`: 34 tests in 4 files, all passing |
| Full static check | 5.6 s | `npm run check`: lint, typecheck, tests, engine purity guard |
| Full demo path in a browser | 6.1 s | Playwright `demo-path.spec.ts`: import → confirm → analyse → resolve every finding → export → privacy assertions |
| All three browser specs | 12.7 s | `npm run test:e2e`, one Chromium worker, axe on the main views |
| Cost per mock run | €0.00, 0 network calls | `callCount: 0` on the stored run; deterministic provider is the default |

The product path is short because the arithmetic is local and the model is
optional. The audit itself is a table join over roster rows; the browser test
includes the whole human checkpoint and still finishes in single-digit seconds.

**Reproducibility:** `npm test` includes the provider-swap test. It asserts that
the `finding_hash` is byte-identical after changing provider. The evaluation of
the mock/template agents is generated by `npm run eval:agents` into
`docs/eval-results.md`, including the failures and known limits.

**Clone to running app:** `npm ci && npm run db:reset && npm run dev`. This exact
sequence was rehearsed in a clean copy with no database and no environment file.

**Not claimed:** hours saved against a manual spreadsheet, a better company as a
result of a faster audit, or prompt quality on a hosted model. Hectic makes the
coverage gap visible earlier; the founder still has to do the interviews.
